## §1 — Slice Objective

Wire the JWT issued by `POST /auth/login` into an actual authentication scheme
(JWT bearer, configured in `Program.cs`) and apply `[Authorize]` to
`AnimalController`'s `Create` action, so `POST /animals` only succeeds for a
request carrying a valid, unexpired token for the seeded `Admin`. Delivered to
full production quality (not simplified for size), with the complete sad-path
test matrix: missing/invalid/expired/tampered token, valid token + invalid
body, and valid token + success.

**Out of scope (deliberately): `POST /animals/{id}/adopt`.** Research
(`docs/research/F0002.1-route-protection.md`) surfaced that `AdoptAnimalHandler`
has a pre-existing DI registration gap (`Program.cs` never registers it)
unrelated to authentication, and that its code path may overlap with another
developer's pending/in-progress work. Rather than (a) bundling an unrelated
defect fix into an auth-wiring PR, or (b) touching code someone else has in
flight, this slice protects `Create` only; `Adopt` and the DI fix move to
`F0002.2` (see parent spec §6 for the full decision record). Consequence:
`POST /animals/{id}/adopt` remains unauthenticated after this slice ships —
PRD gap G4 is only partially closed until `F0002.2` lands.

## §3 — Design *(filled in Design, ~150–200 lines)*

> Architectural decision and the concrete changes. Resolve all open questions from the
> research notes here. No code — decisions and shapes only.

- **Architectural decision:** Standard ASP.NET Core JWT bearer authentication,
  wired inline in `Program.cs` (matching every other DI/middleware registration
  in the file — `CLAUDE.md` notes "no extension-method modules yet," so this
  slice does not introduce one). `AddAuthentication(JwtBearerDefaults.AuthenticationScheme).AddJwtBearer(...)`
  is added to the service collection; `TokenValidationParameters` reuses the
  exact key/issuer/algorithm shape `JwtTokenGenerator.GenerateToken` already
  issues (`JwtTokenGenerator.cs:24-29,37-41`) — same `Jwt:Key`/`Jwt:Issuer`
  config, HMAC-SHA256, no audience. `app.UseAuthentication()` is added
  immediately before the existing `app.UseAuthorization()` (`Program.cs:59`) —
  ASP.NET Core requires this exact order, `UseAuthentication` before
  `UseAuthorization`, or `[Authorize]` never sees an authenticated principal.
  `[Authorize]` is applied to `AnimalController.Create` only (action-level, not
  controller-level — see Q6 below). No new abstraction, no `IOptions<JwtOptions>`
  type, no exception middleware — all rejected as out of proportion to a
  ≤400-line slice; each is recorded as a rejected alternative under the
  relevant open question below.
- **Changes by layer:**
  - **API (`ONG.API`)** — `Program.cs`: add `AddAuthentication`/`AddJwtBearer`
    service registration (placed next to the existing `AddScoped<ITokenGenerator, JwtTokenGenerator>()`
    at L34, since both concern the same JWT concern) and `app.UseAuthentication()`
    (inserted at L58, directly before the existing `app.UseAuthorization()` at
    L59). No change to `JwtTokenGenerator.ValidateConfiguration`'s call site
    (`Program.cs:44`) — it already fails fast on exactly the three config keys
    `AddJwtBearer` will also consume.
    `AnimalController.cs`: add `using Microsoft.AspNetCore.Authorization;` and
    `[Authorize]` on the `Create` action (L21-27) only. `Adopt` (L29-40) is
    untouched — it stays public, per this slice's explicit scope narrowing (§1).
  - **Application (`ONG.Application`)** — `CreateAnimalCommand.cs`: add
    `using System.ComponentModel.DataAnnotations;` and `[Required]` on the
    `Name` property (L7) only. This is the minimum needed to give NFR1's
    "valid token + invalid body → 400" acceptance criterion (parent spec, AC4)
    a concrete, testable lever — see Q5 below. It does not attempt to close
    the broader pre-existing gap ("`CreateAnimalCommand` has zero validation
    attributes," `CLAUDE.md` / research §7) for every field; that remains a
    separate, untracked defect, unchanged by this slice.
  - **Infrastructure (`ONG.Infrastructure`)** — no changes. `JwtTokenGenerator`
    is read, not modified: its existing claims shape (`sub`, `adminId`, no
    `aud`) and `Jwt:Key`/`Jwt:Issuer`/`Jwt:ExpiryMinutes` config are consumed
    as-is by the new `AddJwtBearer` validation parameters.
  - **Persistence** — no changes.
  - **Packaging** — `ONG.API.csproj`: add
    `<PackageReference Include="Microsoft.AspNetCore.Authentication.JwtBearer" Version="10.0.11" />`,
    matching the version already pinned for every other `Microsoft.AspNetCore.*`
    package in this `.csproj` (`Microsoft.AspNetCore.OpenApi` L11,
    `Microsoft.EntityFrameworkCore.Design` L12, both `10.0.11`).
- **Migrations:** none.
- **Explicit reuse:**
  - `JwtTokenGenerator`'s claims/signing-key shape (research §3, bullet 3) —
    `TokenValidationParameters` mirrors it exactly (same key bytes, same
    issuer string, `HmacSha256`), rather than inventing a parallel
    configuration surface.
  - `JwtTokenGenerator.ValidateConfiguration` fail-fast pattern (research §3,
    bullet 1) — reused unchanged (Q3 below), not duplicated for the bearer
    scheme.
  - `LoginApiFactory` (research §3, bullet 2) — reused unmodified as the E2E
    test factory; it already injects `Jwt:Key`/`Jwt:Issuer`/`Jwt:ExpiryMinutes`
    and `AdminSeed:*` config, which is everything this slice's E2E tests need
    to both log in and call the protected endpoint through the same
    `HttpClient`.
  - `LoginEndpointTests`'s `IClassFixture<LoginApiFactory>` + `HttpClient` +
    `PostAsJsonAsync`/`ReadFromJsonAsync<JsonElement>` shape (research §3,
    bullet 3) — reused as the template for the new E2E test class.
  - `LoginCommand`'s `[Required]` precedent (research §3, bullet 5) — reused
    as the pattern for `CreateAnimalCommand.Name`'s new `[Required]` attribute.
- **Resolved open questions** (from `docs/research/F0002.1-route-protection.md` §6):
  - **Q1 (audience):** `ValidateAudience = false`, explicit in
    `TokenValidationParameters`. *Rejected:* adding an `aud` claim to
    `JwtTokenGenerator.GenerateToken` — would modify already-shipped,
    already-tested (`LoginEndpointTests`) token-issuance behavior for no
    functional gain in a single-org, single-audience system.
  - **Q2 (config access):** raw `IConfiguration["Jwt:Key"]`/`["Jwt:Issuer"]`
    indexer, same as `JwtTokenGenerator`. *Rejected:* `IOptions<JwtOptions>` —
    would be the first use of the Options pattern for `Jwt:*` in the repo,
    adding a new type and a new convention for a single consumer, with no
    reuse benefit since `JwtTokenGenerator` itself doesn't use it either.
  - **Q3 (bearer-scheme validation):** reuse `JwtTokenGenerator.ValidateConfiguration`
    as-is, unchanged — it already fail-fast-validates exactly the three keys
    (`Jwt:Key` ≥32 chars, `Jwt:Issuer`, `Jwt:ExpiryMinutes`) that
    `TokenValidationParameters` needs. No additional checks: `AddJwtBearer`
    introduces no new config keys beyond what's already validated.
  - **Q4 (Adopt not-found handling):** not applicable to this slice — `Adopt`/
    `AdoptAnimalHandler` are entirely out of scope (§1); this question moves
    to `F0002.2` unchanged.
  - **Q5 (invalid-body 400 for `Create`):** add `[Required]` to
    `CreateAnimalCommand.Name` only (see Changes by layer above). This
    satisfies the parent spec's AC4 ("valid token + invalid body → 400") with
    the smallest possible footprint; it deliberately does not add validation
    to every field on `CreateAnimalCommand`.
  - **Q6 (`[Authorize]` placement):** action-level, on `Create` only.
    *Rejected:* controller-level `[Authorize]` — would also protect `Adopt`,
    directly contradicting this slice's explicit scope narrowing (§1: "`Adopt`
    remains unauthenticated after this slice ships").
  - **Q7 (E2E token acquisition):** happy-path and invalid-body tests obtain a
    real token by `POST`ing to `/auth/login` through the same `HttpClient`
    first (mirrors `LoginEndpointTests` and a real client's behavior, and
    proves issuance→validation end-to-end). The missing-token test omits the
    header entirely. The tampered-token test takes a real logged-in token and
    mutates one character of its signature segment. The expired-token test
    cannot use a real login (the configured `Jwt:ExpiryMinutes` is 60, too
    long to wait out) — it mints a token directly in the test using
    `JwtSecurityTokenHandler`/`JwtSecurityToken` with the same test key/issuer/
    algorithm as `LoginApiFactory`'s config, but an already-past `expires`.
    This is test-only code (in the new E2E test file), not a change to
    `JwtTokenGenerator`.
  - **Q8 (`AdoptAnimalHandler` DI registration):** not applicable to this
    slice — moves to `F0002.2` unchanged, per the parent spec's already-recorded
    decision (§6 there).

## §4 — Tests BEFORE Implementation (TDD)

> Explicit test list written **before** any implementation. Must include at least
> **1 happy path** and **1 sad path** end-to-end test.

- [ ] *(unit)* `CreateAnimalCommand` with an empty/whitespace `Name` fails
  `DataAnnotations` validation (`Validator.TryValidateObject`, `validateAllProperties: true`)
  with a `ValidationResult` referencing `Name`. Guards the new `[Required]`
  attribute (Q5) directly, independent of the ASP.NET Core pipeline.
- [ ] *(unit)* `CreateAnimalCommand` with all fields populated (including a
  non-empty `Name`) passes `DataAnnotations` validation. Sad-path counterpart's
  happy twin — guards against the new attribute rejecting valid input.
- [ ] *(E2E — happy)* `POST /animals` with a valid, unexpired bearer token
  (obtained via `POST /auth/login` through the same `HttpClient`, mirroring
  `LoginEndpointTests`) and a fully-populated body returns `200 OK`. Maps to
  parent spec AC1 (happy path) and FR2.
- [ ] *(E2E — sad)* `POST /animals` with no `Authorization` header returns
  `401 Unauthorized`, and no `Animal` row is persisted (asserted via a scoped
  `ONGDbContext` resolved from `factory.Services`, same InMemory database).
  Maps to parent spec AC2 (missing credential) and FR3.
- [ ] *(E2E — sad)* `POST /animals` with a syntactically invalid bearer token
  (e.g. `"not-a-jwt"`) returns `401 Unauthorized`. Maps to FR3.
- [ ] *(E2E — sad)* `POST /animals` with a bearer token minted with an
  already-past `expires` (same test key/issuer/algorithm as `LoginApiFactory`)
  returns `401 Unauthorized`, and no `Animal` row is persisted. Maps to parent
  spec AC3 (expired credential) and FR3.
- [ ] *(E2E — sad)* `POST /animals` with a real token obtained via
  `/auth/login`, then tampered (one character of the signature segment
  mutated), returns `401 Unauthorized`. Maps to parent spec AC3 (tampered
  credential) and FR3.
- [ ] *(E2E — sad)* `POST /animals` with a valid bearer token but a body
  missing `Name` returns `400 Bad Request` — proves a valid token does not
  bypass input validation. Maps to parent spec AC4 and NFR1.

using System;
using System.IdentityModel.Tokens.Jwt;
using System.Net;
using System.Net.Http;
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Security.Claims;
using System.Text;
using System.Text.Json;
using System.Threading.Tasks;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.IdentityModel.Tokens;
using ONG.Domain.Entitites;
using ONG.Infrastructure.DataBase;
using Xunit;

namespace ONG.Tests.Api
{
    public class AnimalControllerAuthTests : IClassFixture<LoginApiFactory>
    {
        private const string TestJwtKey = "test-only-signing-key-at-least-32-bytes-long!";
        private const string TestJwtIssuer = "ong-api-tests";

        private readonly LoginApiFactory _factory;
        private readonly HttpClient _client;

        public AnimalControllerAuthTests(LoginApiFactory factory)
        {
            _factory = factory;
            _client = factory.CreateClient();
        }

        private static object ValidAnimalBody() => new
        {
            Name = "Rex",
            Species = "Dog",
            Sex = "Male",
            Size = "Medium",
            Description = "Friendly dog",
            approximateAge = 2,
            Image = "https://example.com/dog.jpg",
            Status = "Available",
            District = "Centro",
            City = "Sao Paulo"
        };

        private async Task<string> GetValidTokenAsync()
        {
            var response = await _client.PostAsJsonAsync("/auth/login", new
            {
                Username = "fernanda",
                Password = "S3nhaForte!"
            });
            var body = await response.Content.ReadFromJsonAsync<JsonElement>();
            return body.GetProperty("token").GetString()!;
        }

        private static string MintExpiredToken()
        {
            var signingKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(TestJwtKey));
            var credentials = new SigningCredentials(signingKey, SecurityAlgorithms.HmacSha256);

            var token = new JwtSecurityToken(
                issuer: TestJwtIssuer,
                claims: new[] { new Claim(JwtRegisteredClaimNames.Sub, "fernanda") },
                expires: DateTime.UtcNow.AddMinutes(-5),
                signingCredentials: credentials);

            return new JwtSecurityTokenHandler().WriteToken(token);
        }

        private static string TamperToken(string token)
        {
            var segments = token.Split('.');
            var signature = segments[2];
            var mutatedChar = signature[0] == 'A' ? 'B' : 'A';
            segments[2] = mutatedChar + signature.Substring(1);
            return string.Join('.', segments);
        }

        private int CountPersistedAnimals()
        {
            using var scope = _factory.Services.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<ONGDbContext>();
            return db.Set<Animal>().Count();
        }

        [Fact]
        public async Task Create_ValidToken_Returns200()
        {
            var token = await GetValidTokenAsync();
            _client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);

            var response = await _client.PostAsJsonAsync("/animals", ValidAnimalBody());

            Assert.Equal(HttpStatusCode.OK, response.StatusCode);
        }

        [Fact]
        public async Task Create_NoAuthorizationHeader_Returns401AndDoesNotPersist()
        {
            var countBefore = CountPersistedAnimals();

            var response = await _client.PostAsJsonAsync("/animals", ValidAnimalBody());

            Assert.Equal(HttpStatusCode.Unauthorized, response.StatusCode);
            Assert.Equal(countBefore, CountPersistedAnimals());
        }

        [Fact]
        public async Task Create_MalformedToken_Returns401()
        {
            _client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", "not-a-jwt");

            var response = await _client.PostAsJsonAsync("/animals", ValidAnimalBody());

            Assert.Equal(HttpStatusCode.Unauthorized, response.StatusCode);
        }

        [Fact]
        public async Task Create_ExpiredToken_Returns401AndDoesNotPersist()
        {
            var countBefore = CountPersistedAnimals();
            var token = MintExpiredToken();
            _client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);

            var response = await _client.PostAsJsonAsync("/animals", ValidAnimalBody());

            Assert.Equal(HttpStatusCode.Unauthorized, response.StatusCode);
            Assert.Equal(countBefore, CountPersistedAnimals());
        }

        [Fact]
        public async Task Create_TamperedToken_Returns401()
        {
            var token = await GetValidTokenAsync();
            var tampered = TamperToken(token);
            _client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", tampered);

            var response = await _client.PostAsJsonAsync("/animals", ValidAnimalBody());

            Assert.Equal(HttpStatusCode.Unauthorized, response.StatusCode);
        }

        [Fact]
        public async Task Create_ValidTokenMissingName_Returns400()
        {
            var token = await GetValidTokenAsync();
            _client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);

            var response = await _client.PostAsJsonAsync("/animals", new
            {
                Species = "Dog",
                Sex = "Male",
                Size = "Medium",
                Description = "Friendly dog",
                approximateAge = 2,
                Image = "https://example.com/dog.jpg",
                Status = "Available",
                District = "Centro",
                City = "Sao Paulo"
            });

            Assert.Equal(HttpStatusCode.BadRequest, response.StatusCode);
        }
    }
}
