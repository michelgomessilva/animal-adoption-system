## §1 — Slice Objective

**Revised 2026-08-25** (see parent `F0004`'s Context/Motivation scope revision):
introduce a single, static client identity sourced from configuration/secrets —
no persisted `Client` entity, no migration, no seeder — and expose
`POST /oauth/token` so the configured client can exchange its `client_id`/
`client_secret` pair for a short-lived client access token. This slice delivers
the config-backed credential and the issuance endpoint end to end; it does
**not** enforce that token on any existing route (that global enforcement,
including malformed-header handling, is `F0004.2`). Runtime revocation without
redeploy (originally FR4/G6) is deferred, not delivered by this slice. Scope is
bounded by FR1/FR2 and NFR1/NFR2 of the parent feature spec.

## §3 — Design *(filled in Design, ~150–200 lines)*

> research notes here. No code — decisions and shapes only.

### Architectural decision

Plain Command+Handler use case (`UseCases/OAuth/IssueClientToken/`), following the exact
`LoginCommand`/`LoginHandler` shape — no new sub-system. The single static client
credential is exposed to `ONG.Application` through a new dependency-inverted
`IClientCredentialsProvider` interface (Application) / `ClientCredentialsProvider`
implementation (Infrastructure, reads `IConfiguration` directly) — mirroring the existing
`IAdminRepository`/`AdminRepository` inversion, so the Handler never touches
`IConfiguration` or `ONG.Infrastructure` directly, keeping the dependency-inversion rule
intact even though there's no database involved. `ITokenGenerator`/`JwtTokenGenerator` is
**extended** (not parallelled) with a second method, `GenerateClientToken(string clientId,
int expiryMinutes)`, sharing a private `BuildToken(claims, issuer, expiryMinutes)` helper
refactored out of the existing `GenerateToken(Admin)` — this is the only way to reuse the
JWT-building code (`SymmetricSecurityKey`/`SigningCredentials`/`JwtSecurityTokenHandler`)
without duplicating it, and it's a pure internal refactor of `JwtTokenGenerator` with zero
change to `GenerateToken(Admin)`'s external behavior or `Jwt:*` config usage.

**Security-critical decision — distinct issuer, shared key.** Client tokens reuse the
existing `Jwt:Key` (signing secret) but are issued under a **distinct, hardcoded issuer**
(`JwtTokenGenerator.ClientTokenIssuer = "ong-api-oauth-clients"`), not the configured
`Jwt:Issuer` used for admin tokens. Reusing `Jwt:Issuer` verbatim would mean a client
token — mintable by anyone holding `front-web`'s semi-public credential — passes the
*existing* `[Authorize]` on `POST /animals`/`PUT /animals/{id}` the moment this slice
ships (`AddJwtBearer`'s default validation only checks token validity + `ValidIssuer =
Jwt:Issuer`, not specific claims), silently granting admin access before F0004.2's
enforcement even exists. Issuing under a different issuer means `AddJwtBearer`'s existing
`ValidIssuer = Jwt:Issuer` check rejects a client token on admin routes immediately, as a
structural side effect of this slice — no change to `Program.cs`'s existing
`AddJwtBearer(...)` call or to `[Authorize]` is needed to satisfy the parent spec's
"a valid client token alone never grants admin access" requirement. F0004.2 will add its
*own* validation path (its own scheme/policy or manual validation) that positively accepts
`ClientTokenIssuer` on the routes it protects; this slice makes no assumption about what
that looks like. Expiry uses a new `ClientCredentials:ExpiryMinutes` key, not `Jwt:ExpiryMinutes`
(NFR1 requires materially shorter-lived tokens than the admin default of 60 minutes).

Claim shape is deliberately minimal: `sub` = `clientId` only. No `token_type`/`scope`
claim is added speculatively for F0004.2's benefit — F0004.2 is a separate spec and will
decide its own enforcement/claim needs during its own research/design phase.

The request/response bodies use this API's existing JSON convention (matching
`LoginCommand`/`LoginResult` — a `[FromBody]`-bound Command, not RFC 6749's
form-urlencoded body), but field names use RFC 6749's OAuth vocabulary in snake_case via
explicit `[JsonPropertyName]` attributes (`grant_type`, `client_id`, `client_secret` on
the request; `access_token`, `token_type`, `expires_in` on the response) — this endpoint
is explicitly framed as "OAuth 2 Client Credentials" by the parent spec, and future
integrations (mobile, per Context) are more likely to bring an OAuth-aware HTTP client
than to expect this codebase's internal camelCase convention.

### Changes by layer

- **`ONG.API`** — new `OAuthController` (`[Route("oauth")]`, `[HttpPost("token")]`,
  bare route mirroring `AuthController`'s `[Route("auth")]`, not `AnimalController`'s
  `api/` prefix — resolves Q4). Explicit null-check → `Unauthorized(new { message =
  "Invalid client_id or client_secret." })` on handler-returned `null`, `Ok(result)` on
  success — same shape as `AuthController.Login`. `Program.cs`: register
  `Configure<ClientCredentialsOptions>`-free direct config read (no `IOptions<T>` — see
  rationale below), `AddScoped<IClientCredentialsProvider, ClientCredentialsProvider>()`,
  `AddScoped<IssueClientTokenHandler>()`, and call
  `ClientCredentialsProvider.ValidateConfiguration(builder.Configuration)` alongside the
  existing `JwtTokenGenerator.ValidateConfiguration` call, before `Migrate()`/`AdminSeeder.Seed`
  in the same startup scope (fail-fast precedent). `appsettings.json`: add
  `ClientCredentials:ExpiryMinutes` default (`15`) — `ClientId`/`ClientSecret` stay
  secret-only (no committed default), same as `Jwt:Key`. `.env.example`: add
  `CLIENT_ID`/`CLIENT_SECRET` entries mapping to `ClientCredentials__ClientId`/
  `ClientCredentials__ClientSecret`, documented like the existing `JWT_KEY` entry.
- **`ONG.Application`** — new `UseCases/OAuth/IssueClientToken/` folder:
  `IssueClientTokenCommand` (`GrantType`/`ClientId`/`ClientSecret`, `[Required]`,
  `GrantType` additionally `[RegularExpression("^client_credentials$")]` — a wrong/missing
  `grant_type` model-binds to a 400 via the existing `[ApiController]` automatic
  ModelState behavior, same mechanism `LoginCommand`'s `[Required]` fields already rely
  on), `IssueClientTokenResult` (`AccessToken`, `TokenType = "Bearer"`, `ExpiresIn`
  seconds), `IssueClientTokenHandler` (constructor-injects `IClientCredentialsProvider` +
  `ITokenGenerator`; compares both `ClientId` and `ClientSecret` via
  `CryptographicOperations.FixedTimeEquals` — constant-time per NFR2 — and returns `null`
  if *either* mismatches, never distinguishing which, before generating a token). New
  `Security/IClientCredentialsProvider.cs` (`ClientCredentials GetConfiguredClient();`
  returning a small `record ClientCredentials(string ClientId, string ClientSecret, int
  ExpiryMinutes)`). `ITokenGenerator` gains `GenerateClientToken(string clientId, int
  expiryMinutes)`.
- **`ONG.Infrastructure`** — new `Security/ClientCredentialsProvider.cs`: instance
  `GetConfiguredClient()` reads `ClientCredentials:ClientId`/`ClientSecret`/`ExpiryMinutes`
  from injected `IConfiguration` (same constructor-injection shape `JwtTokenGenerator`
  already uses); static `ValidateConfiguration(IConfiguration)` fail-fast-throws one
  `InvalidOperationException` listing every missing/invalid key (`ClientId` non-empty,
  `ClientSecret` non-empty and ≥16 chars, `ExpiryMinutes` a valid int in `1..60`) —
  mirrors `AdminSeeder.ValidateConfiguration`/`JwtTokenGenerator.ValidateConfiguration`
  exactly. `JwtTokenGenerator.cs`: add `GenerateClientToken`, extract private `BuildToken`
  helper (refactor only, `GenerateToken(Admin)` behavior unchanged), add `private const
  string ClientTokenIssuer = "ong-api-oauth-clients"`.
- **`ONG.Domain`** — no changes (no entity — this is this slice's core scope revision).

### Migrations

None — no persisted entity (per the 2026-08-25 parent scope revision; `DB Impact` in the
parent spec already states this explicitly).

### Explicit reuse

- `LoginCommand`/`LoginHandler`/`AuthController.Login`'s null-check → `Unauthorized(...)`
  shape (research §3) — copied for `IssueClientTokenCommand`/`Handler`/`OAuthController`.
- `AdminSeeder.ValidateConfiguration`/`JwtTokenGenerator.ValidateConfiguration`'s
  accumulate-all-errors-then-throw-one-exception fail-fast pattern (research §3) — copied
  for `ClientCredentialsProvider.ValidateConfiguration`.
- `IAdminRepository`/`AdminRepository` dependency-inversion shape (research §3) — copied
  for `IClientCredentialsProvider`/`ClientCredentialsProvider`, despite no database
  involvement, to keep Application decoupled from `IConfiguration`/Infrastructure.
- `JwtTokenGenerator`'s existing `SymmetricSecurityKey`/`SigningCredentials`/
  `JwtSecurityTokenHandler` JWT-building code (research §1) — reused via extracted
  `BuildToken` helper instead of a parallel token generator (resolves Q1).
- Existing `Jwt:Key` signing secret (research §3/§4) — reused as-is for client tokens;
  no second signing key introduced.

### Resolved open questions (from research §6)

- **Q1** (reuse vs. parallel `ITokenGenerator`) — **Reuse.** Extend `ITokenGenerator`
  with `GenerateClientToken`; share the JWT-building helper. A parallel generator would
  duplicate the exact same JWT-construction code for no benefit.
- **Q2** (shared vs. separate `Jwt:*` config) — **Hybrid.** Share `Jwt:Key` (signing
  secret); use a new `ClientCredentials:ExpiryMinutes` (not `Jwt:ExpiryMinutes`, per
  NFR1); use a distinct **hardcoded** issuer (`ClientTokenIssuer`, not `Jwt:Issuer`,
  not separately configurable) — see the Security-critical decision above.
- **Q3** (config shape) — Superseded by the 2026-08-25 scope revision: no `ClientSeed`-
  equivalent seeder. Config is `ClientCredentials:ClientId`/`ClientCredentials:ClientSecret`/
  `ClientCredentials:ExpiryMinutes`, read directly (via `IClientCredentialsProvider`), no
  persistence, single client only (matches FR1's single known application, `front-web`).
- **Q4** (route placement) — New bare `[Route("oauth")]` controller (`OAuthController`),
  `[HttpPost("token")]` → `POST /oauth/token`, mirroring `AuthController`'s bare-route
  convention, not folded into `AuthController` (different aggregate/concern) and not
  `api/`-prefixed (matches the Public Contracts table's exact path).
- **Q5** (entity shape) — **Moot.** No `Client` entity exists in this slice (2026-08-25
  scope revision, confirmed in `§1 Slice Objective` and parent `DB Impact`).
- **Q6** (`PasswordHasher<Client>` / timing normalization) — **Moot for hashing** (parent
  `Dependencies`, revised 2026-08-25: no persisted secret, no `IPasswordHasher<T>`).
  Timing-safety is still required (NFR2) and is delivered via
  `CryptographicOperations.FixedTimeEquals` on both `ClientId` and `ClientSecret`, with a
  single generic failure path that doesn't distinguish which one was wrong.
- **Q7** (response shape / `expires_in`) — **Yes**, add expiry to the response. Decided
  on the standard OAuth2 shape (`access_token`/`token_type`/`expires_in`, snake_case via
  `[JsonPropertyName]`) rather than reusing `LoginResult`'s bare `Token` property — see
  the JSON-naming rationale in the Architectural decision above.

```csharp
public class JwtTokenGenerator : ITokenGenerator
{
    private const string ClientTokenIssuer = "ong-api-oauth-clients";

    private readonly IConfiguration _configuration;

    public JwtTokenGenerator(IConfiguration configuration)
    {
        _configuration = configuration;
    }

    public string GenerateToken(Admin admin)
    {
        var issuer = _configuration["Jwt:Issuer"]!;
        var expiryMinutes = int.Parse(_configuration["Jwt:ExpiryMinutes"]!);

        var claims = new List<Claim>
        {
            new Claim(JwtRegisteredClaimNames.Sub, admin.Username),
            new Claim("adminId", admin.Id.ToString())
        };

        return BuildToken(claims, issuer, expiryMinutes);
    }

    public string GenerateClientToken(string clientId, int expiryMinutes)
    {
        var claims = new List<Claim>
        {
            new Claim(JwtRegisteredClaimNames.Sub, clientId)
        };

        return BuildToken(claims, ClientTokenIssuer, expiryMinutes);
    }

    private string BuildToken(List<Claim> claims, string issuer, int expiryMinutes)
    {
        var key = _configuration["Jwt:Key"]!;
        var signingKey = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(key));
        var credentials = new SigningCredentials(signingKey, SecurityAlgorithms.HmacSha256);

        var token = new JwtSecurityToken(
            issuer: issuer,
            claims: claims,
            expires: DateTime.UtcNow.AddMinutes(expiryMinutes),
            signingCredentials: credentials);

        return new JwtSecurityTokenHandler().WriteToken(token);
    }

    // MinimumKeyLength and ValidateConfiguration stay exactly as they are today.
```
(Leave `MinimumKeyLength` and `ValidateConfiguration` exactly as-is beneath this, then

```csharp
using System;
using System.Collections.Generic;
using Microsoft.Extensions.Configuration;
using ONG.Application.Security;

namespace ONG.Infrastructure.Security
{
    public class ClientCredentialsProvider : IClientCredentialsProvider
    {
        private const int MinimumSecretLength = 16;
        private const int MinExpiryMinutes = 1;
        private const int MaxExpiryMinutes = 60;

        private readonly IConfiguration _configuration;

        public ClientCredentialsProvider(IConfiguration configuration)
        {
            _configuration = configuration;
        }

        public ClientCredentials GetConfiguredClient()
        {
            var clientId = _configuration["ClientCredentials:ClientId"]!;
            var clientSecret = _configuration["ClientCredentials:ClientSecret"]!;
            var expiryMinutes = int.Parse(_configuration["ClientCredentials:ExpiryMinutes"]!);

            return new ClientCredentials(clientId, clientSecret, expiryMinutes);
        }

        public static void ValidateConfiguration(IConfiguration configuration)
        {
            var missing = new List<string>();

            if (string.IsNullOrWhiteSpace(configuration["ClientCredentials:ClientId"]))
            {
                missing.Add("ClientCredentials:ClientId");
            }

            var secret = configuration["ClientCredentials:ClientSecret"];
            if (string.IsNullOrWhiteSpace(secret))
            {
                missing.Add("ClientCredentials:ClientSecret");
            }
            else if (secret.Length < MinimumSecretLength)
            {
                missing.Add(
                    $"ClientCredentials:ClientSecret (must be at least {MinimumSecretLength} characters long)");
            }

            var expiryMinutes = configuration["ClientCredentials:ExpiryMinutes"];
            if (string.IsNullOrWhiteSpace(expiryMinutes))
            {
                missing.Add("ClientCredentials:ExpiryMinutes");
            }
            else if (!int.TryParse(expiryMinutes, out var parsedExpiry)
                || parsedExpiry < MinExpiryMinutes || parsedExpiry > MaxExpiryMinutes)
            {
                missing.Add(
                    $"ClientCredentials:ExpiryMinutes (must be an integer between {MinExpiryMinutes} and {MaxExpiryMinutes})");
            }

            if (missing.Count > 0)
            {
                throw new InvalidOperationException(
                    $"Missing required configuration key(s): {string.Join(", ", missing)}. " +
                    "These are required to issue client access tokens; the application " +
                    "cannot start without them.");
            }
        }
    }
}
```

```csharp
using System.Security.Cryptography;
using System.Text;
using ONG.Application.Security;

namespace ONG.Application.UseCases.OAuth.IssueClientToken
{
    public class IssueClientTokenHandler
    {
        private readonly IClientCredentialsProvider _clientCredentialsProvider;
        private readonly ITokenGenerator _tokenGenerator;

        public IssueClientTokenHandler(
            IClientCredentialsProvider clientCredentialsProvider, ITokenGenerator tokenGenerator)
        {
            _clientCredentialsProvider = clientCredentialsProvider;
            _tokenGenerator = tokenGenerator;
        }

        public IssueClientTokenResult? Handle(IssueClientTokenCommand command)
        {
            var configured = _clientCredentialsProvider.GetConfiguredClient();

            var clientIdMatches = CryptographicOperations.FixedTimeEquals(
                Encoding.UTF8.GetBytes(command.ClientId), Encoding.UTF8.GetBytes(configured.ClientId));
            var clientSecretMatches = CryptographicOperations.FixedTimeEquals(
                Encoding.UTF8.GetBytes(command.ClientSecret), Encoding.UTF8.GetBytes(configured.ClientSecret));

            if (!clientIdMatches || !clientSecretMatches)
            {
                return null;
            }

            var token = _tokenGenerator.GenerateClientToken(configured.ClientId, configured.ExpiryMinutes);
            return new IssueClientTokenResult(token, configured.ExpiryMinutes * 60);
        }
    }
}
```

(`CryptographicOperations.FixedTimeEquals` returns `false` immediately, without throwing,
when the two spans differ in length — safe for comparing arbitrary-length attacker input
against the configured secret.)

using System.Net;
using System.Net.Http;

namespace ONG.Tests.Api

                client_id = OAuthApiFactory.ConfiguredClientId,

            Assert.True(body.GetProperty("expires_in").GetInt32() > 0);

        [Fact]
        public async Task Token_WrongClientSecret_Returns401WithGenericMessage()
        {
            var response = await _client.PostAsJsonAsync("/oauth/token", new

                client_id = OAuthApiFactory.ConfiguredClientId,
                client_secret = "wrong-secret-value"
            });

            var body = await response.Content.ReadFromJsonAsync<JsonElement>();
            Assert.Equal("Invalid client_id or client_secret.", body.GetProperty("message").GetString());
        }

        [Fact]
        public async Task Token_MissingClientId_Returns400()

            var response = await _client.PostAsJsonAsync("/oauth/token", new
            {
                grant_type = "client_credentials",
