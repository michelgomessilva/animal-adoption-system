## §1 — Slice Objective

> The smallest end-to-end vertical increment this slice delivers. One short paragraph.

Add optional query-string filters (`species`, `sex`, `size`, `district`, `city`,
and — admin-only — `status`) plus an optional `orderBy` sort parameter to the
`GET /api/animals` endpoint delivered by `F0003.1`, so callers can narrow and
order the result set without widening visibility past the rule already
enforced there (anonymous/bad-token callers still see only `Available`
animals, regardless of any `status` value they pass). Includes `400` handling
for a filter or sort value that doesn't match a known field/enum. This is the
second and final slice of `F0003-public-animal-listing`.

## §3 — Design *(filled in Design, ~150–200 lines)*

> Architectural decision and the concrete changes. Resolve all open questions from the
> research notes here. No code — decisions and shapes only.

### Architectural decision

Push filtering **and** sorting down into `AnimalRepository` as a composed EF Core
`IQueryable` (conditional `.Where()`/`.OrderBy()` chained on a single query,
materialized once via `.ToList()`), rather than continuing the current
in-memory `.Where()` pattern (`ListAnimalsHandler.cs:21–23`). This is a
deliberate deviation from the only existing precedent in the repo, driven by
NFR3 ("Query construction for any filter must use EF Core's parameterized
LINQ query building") — a post-`GetAll()` in-memory filter no longer
satisfies that once `GetAll()` itself takes filter parameters instead of
returning everything. It also collapses visibility-scoping and filtering into
one DB round trip instead of two conceptual passes.

Raw query-string values are bound as `string?` (not native enum types) on
`ListAnimalsCommand`, and parsed/validated by hand in `ListAnimalsHandler`
using `Enum.TryParse(..., ignoreCase: true, ...)` guard clauses that throw
`ArgumentException` on failure — mirroring `CreateAnimalHandler`'s existing
guard-clause pattern, already wired through `ExceptionHandlingMiddleware` to
`400`. This sidesteps relying on ASP.NET Core's default `[FromQuery]` enum
model-binder behavior for invalid values, which is unobserved/undetermined in
this codebase (research §6 Q4) — binding as `string?` means there is nothing
for the framework's default binder to reject or silently coerce; the
Handler is the single source of truth for "invalid" everywhere in this slice,
exactly as it already is for `Create`.

A new `AnimalFilter` type (Application layer, alongside `IAnimalRepository`)
carries the parsed, strongly-typed, optional filter/sort criteria across the
Application → Infrastructure boundary — the repository never sees raw
strings, only validated enum/typed values.

**Alternative rejected:** keep the in-memory `.Where()` pattern and add
filtering as a second in-memory pass after `GetAll()`. Rejected because it
directly contradicts NFR3 once `GetAll()` grows filter parameters, and
because it would materialize the entire table before filtering, which is
strictly worse than what's being replaced.

### Changes by layer

- **`ONG.Domain`** — no changes. No new entity/enum needed; existing
  `Species`/`Sex`/`Size`/`Status` enums are reused as-is for filter parsing.
- **`ONG.Application`**:
  - `ListAnimalsCommand` gains six nullable `string?` properties, model-bound
    via `[FromQuery]`: `Species`, `Sex`, `Size`, `Status`, `District`, `City`,
    plus `OrderBy`. `IsAuthenticated` stays as-is (never bound from the
    query string — see Q6 below).
  - New `AnimalFilter` (`ONG.Application/Repositories/AnimalFilter.cs`):
    `Species? Species`, `Sex? Sex`, `Size? Size`, `Status? Status`,
    `string? District`, `string? City`, `AnimalSortField? OrderBy`,
    `bool OrderDescending`.
  - New `AnimalSortField` enum (`ONG.Application/Repositories/AnimalSortField.cs`):
    `Name, Species, Size, CreatedAt` — an Application-layer query concern, not
    domain vocabulary, so it does not belong in `ONG.Domain`.
  - `IAnimalRepository.GetAll()` → `IAnimalRepository.GetAll(AnimalFilter filter)`
    (still synchronous, matching every other repository method — Q on sync
    vs. async is not reopened, per research §7).
  - `ListAnimalsHandler.Handle`: parses `command`'s raw strings into an
    `AnimalFilter` (guard clauses → `ArgumentException` → `400` on any
    unrecognized enum value or `orderBy` token), applies the anonymous-caller
    visibility override (see Q5 below), and calls
    `_repository.GetAll(filter)` directly — no post-filtering in the Handler
    anymore.
- **`ONG.Infrastructure`** — `AnimalRepository.GetAll(AnimalFilter filter)`
  builds `IQueryable<Animal> query = _context.Animals` then conditionally
  chains `.Where(a => a.Species == filter.Species.Value)` (same shape for
  `Sex`/`Size`/`Status`), `.Where(a => a.District.ToLower() == filter.District.ToLower())`
  (same shape for `City`, case-insensitive per research §7's casing risk;
  trimmed by the Handler before reaching here), and a conditional
  `.OrderBy(...)`/`.OrderByDescending(...)` switch over `AnimalSortField`,
  ending in one `.ToList()`. No filter clause is added for a `null` property.
- **`ONG.API`** — `AnimalController.List` becomes
  `List([FromQuery] ListAnimalsCommand command)`; immediately after binding,
  the controller overwrites `command.IsAuthenticated =
  HttpContext.User.Identity?.IsAuthenticated ?? false` before calling the
  Handler, same as today — this keeps the identity flag server-controlled
  and unspoofable via query string even though it now shares the bound
  Command type. No new DTO (NFR1) — response is still `Ok(animals)`.

### Migrations

None. No schema change (parent spec DB Impact section) and no new index —
per research §7 this is accepted at NFR2's stated MVP scale; a
performance-driven index is explicitly deferred to a future slice if ever
needed.

### Resolved open questions

- **Q1 (admin vs. authenticated for `status`)** — reuse `IsAuthenticated` as
  the sole signal, exactly as FR3 already does for full-catalog visibility.
  There is exactly one identity type in the system (research §5); "any
  authenticated caller" and "admin" are the same thing today. No new
  role/claim is introduced.
- **Q2 (in-memory vs. pushed-down filtering)** — pushed down into
  `AnimalRepository` as a composed `IQueryable`. See Architectural decision
  above; driven by NFR3.
- **Q3 (400 mechanism)** — Handler-thrown `ArgumentException` via
  `Enum.TryParse` guard clauses, reusing `ExceptionHandlingMiddleware`.
  `[ApiController]`'s automatic `ModelState` `DataAnnotations` path is not
  used for query-string filters — that mechanism validates presence/shape on
  `[FromBody]` commands, not free-form enum parsing, and reusing it here
  would depend on the very model-binder behavior Q4 flags as undetermined.
- **Q4 (default `[FromQuery]` enum-binder behavior)** — moot: filter
  properties bind as `string?`, so no enum model binder is ever invoked by
  the framework for these parameters. All parsing/validation is explicit,
  in the Handler.
- **Q5 (anonymous + `status` filter composition)** — **ignored, not
  intersected.** A non-authenticated caller's `status` value is still
  validated (`400` if it isn't a recognized `Status` enum value — the
  Security Considerations section requires this regardless of the visibility
  outcome), but the *effective* filter passed to the repository is always
  forced to `Status = Available` for that caller, discarding whatever value
  they requested. Rejected alternative: intersecting the requested status
  with `Available` (e.g., `status=Adopted` as anonymous → empty list).
  Rejected because it produces a confusing, silently-empty result that reads
  like a bug rather than a boundary, and because the parent spec's own
  wording — "still gets `200` scoped to `Available` only" — reads more
  naturally as "the anonymous view, unchanged" than as "an empty
  intersection."
- **Q6 (`ListAnimalsCommand`'s shape)** — properties added directly to
  `ListAnimalsCommand`, bound via `[FromQuery]` on the controller action
  parameter (no separate query/filter DTO). `IsAuthenticated` is excluded
  from being trusted post-binding — the controller always overwrites it from
  `HttpContext.User.Identity` right after binding, so a caller cannot spoof
  it via `?isAuthenticated=true`.
- **Q7 (`orderBy` grammar and sortable fields)** — grammar: `orderBy={field}`
  (ascending, default) or `orderBy={field}_desc` (descending), case-insensitive,
  no `_asc` variant (redundant with the default). Sortable field whitelist:
  `name`, `species`, `size`, `createdAt` (`AnimalSortField` enum) — chosen as
  the fields most useful for browsing a small MVP catalog; `sex`/`district`/
  `city`/`status` remain filterable but are not offered as sort keys (no
  natural/meaningful ordering, keeps the whitelist small). Any other token
  (unrecognized field, or a recognized field misspelled) → `400`.

### Known limitation carried into this slice (not fixed here)

Research §7 flagged that `Animal`'s constructor never assigns `Species`
(every persisted animal's `Species` is stuck at `Species.None`), a
pre-existing defect out of this slice's scope (recommended as its own
hotfix per the parent feature spec). Consequence for this slice: the
`species` filter is fully implemented (parsed, validated, pushed into the
query) but **cannot be demonstrated matching real non-`None` data** through
any code path in this codebase today, since every construction path for
`Animal` — production and test alike — routes through the same buggy
constructor. `None` itself is rejected as an invalid filter value (it is a
sentinel, not a real adoptable species), so a *valid* `species` filter
(`Dog`/`Cat`) will correctly — if unhelpfully — match zero animals until the
constructor bug is fixed. Tests below cover the filter's parsing/plumbing
correctness and this exact documented behavior, not a true positive match;
`sex`/`size`/`district`/`city`/`status` (all correctly assigned today) carry
the positive-match filter coverage instead.

using ONG.Domain.Entitites;

namespace ONG.Application.UseCases.Animals.ListAnimals
{
    public class ListAnimalsHandler
    {
        private readonly IAnimalRepository _repository;

        public ListAnimalsHandler(IAnimalRepository repository)
        {
            _repository = repository;
        }

        public List<Animal> Handle(ListAnimalsCommand command)
        {
            var filter = new AnimalFilter
            {
                Species = ParseFilterEnum<Species>(command.Species, nameof(command.Species)),
                Sex = ParseFilterEnum<Sex>(command.Sex, nameof(command.Sex)),
                Size = ParseFilterEnum<Size>(command.Size, nameof(command.Size)),
                Status = ParseFilterEnum<Status>(command.Status, nameof(command.Status)),
                District = string.IsNullOrWhiteSpace(command.District) ? null : command.District.Trim(),
                City = string.IsNullOrWhiteSpace(command.City) ? null : command.City.Trim()
            };

            if (filter.Species == Species.None)
                throw new ArgumentException($"{nameof(command.Species)} filter value 'None' is not a valid filter");

            var animals = _repository.GetAll(filter);

            return command.IsAuthenticated
                ? animals
                : animals.Where(a => a.Status == Status.Available).ToList();
        }

        private static TEnum? ParseFilterEnum<TEnum>(string? rawValue, string fieldName)
            where TEnum : struct, Enum
        {
            if (string.IsNullOrWhiteSpace(rawValue))
                return null;

            if (!Enum.TryParse<TEnum>(rawValue, ignoreCase: true, out var parsed))
                throw new ArgumentException($"{fieldName} filter value '{rawValue}' is not recognized");

            return parsed;
        }
    }
}

private static void ApplyOrderBy(string? rawOrderBy, AnimalFilter filter)
{
    if (string.IsNullOrWhiteSpace(rawOrderBy))
        return;

    const string descendingSuffix = "_desc";
    var descending = rawOrderBy.EndsWith(descendingSuffix, StringComparison.OrdinalIgnoreCase);
    var fieldToken = descending
        ? rawOrderBy[..^descendingSuffix.Length]
        : rawOrderBy;

    if (!Enum.TryParse<AnimalSortField>(fieldToken, ignoreCase: true, out var field))
        throw new ArgumentException($"orderBy value '{rawOrderBy}' is not recognized");

    filter.OrderBy = field;
    filter.OrderDescending = descending;
}

public List<Animal> GetAll(AnimalFilter filter)
{
    IQueryable<Animal> query = _context.Animals;

    if (filter.Species.HasValue)
        query = query.Where(a => a.Species == filter.Species.Value);

    if (filter.Sex.HasValue)
        query = query.Where(a => a.Sex == filter.Sex.Value);

    if (filter.Size.HasValue)
        query = query.Where(a => a.Size == filter.Size.Value);

    if (filter.Status.HasValue)
        query = query.Where(a => a.Status == filter.Status.Value);

    if (!string.IsNullOrEmpty(filter.District))
        query = query.Where(a => a.District.ToLower() == filter.District.ToLower());

    if (!string.IsNullOrEmpty(filter.City))
        query = query.Where(a => a.City.ToLower() == filter.City.ToLower());

    return query.ToList();
}
