# CODE REVIEW: Avaliação Técnica Sênior

## 1. Arquitetura e Padrões de Design
* **Análise Arquitetural:**
  - **Identificação da Arquitetura:** O projeto adota uma arquitetura em camadas inspirada nos princípios de *Clean Architecture* e *Hexagonal Architecture*, dividida formalmente em 4 projetos principais: `ONG.Domain`, `ONG.Application`, `ONG.Infrastructure` e `ONG.API` (além da suíte de testes em `ONG.Tests`).
  - **Separação de Conceitos (Separation of Concerns):** 
    - *Pontos Fortes:* A direção das dependências entre os projetos (`.csproj`) respeita a regra da Clean Architecture. O projeto `ONG.Domain` não possui nenhuma dependência externa; `ONG.Application` depende apenas do Domínio; `ONG.Infrastructure` e `ONG.API` dependem de Application e Domain.
    - *Erros Estruturais e Vazamentos de Camadas (Layer Leaks):*
      1. **Exposição Direta de Entidades de Domínio na API:** Os Controllers (ex: [AnimalController.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Controllers/AnimalController.cs)) retornam instâncias da entidade de domínio `Animal` diretamente nas respostas HTTP (`return StatusCode(201, animal);`, `return Ok(animals);`). Falta uma camada de DTOs/ViewModels de Saída (*Response DTOs*). Isso acopla a resposta da API REST ao modelo interno do banco e impede a evolução independente de ambos.
      2. **Vazamento de Validações Web na Camada de Aplicação:** Os DTOs de entrada em `Application` (ex: [CreateAnimalCommand.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/CreateAnimal/CreateAnimalCommand.cs)) utilizam atributos de `System.ComponentModel.DataAnnotations` (`[Required]`, `[StringLength]`, `[Range]`). A camada de Application não deveria depender de anotações do ecossistema ASP.NET/Web para validação.
      3. **Dependência do Identity na Application:** O projeto [ONG.Application.csproj](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/ONG.Application.csproj) importa o pacote `Microsoft.Extensions.Identity.Core` apenas para utilizar a interface `IPasswordHasher<Admin>`, acoplando a aplicação ao framework de identidade da Microsoft em vez de declarar uma abstração própria.
      4. **Typo Estrutural no Namespace:** A pasta de entidades no projeto de Domínio foi nomeada como `Entitites` (com `t` duplicado), resultando no namespace incorreto `ONG.Domain.Entitites`.

* **Design Patterns:**
  - **Repository Pattern:**
    - Implementado através de [IAnimalRepository.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/Repositories/IAnimalRepository.cs) / [AnimalRepository.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/Repositories/AnimalRepository.cs) e [IAdminRepository.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/Repositories/IAdminRepository.cs) / [AdminRepository.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/Repositories/AdminRepository.cs).
    - *Avaliação Sênior:* Em projetos .NET modernos com Entity Framework Core, o Repository Pattern customizado muitas vezes atua como uma abstração redundante (*anti-pattern*) se apenas repassa chamadas ao `DbSet` sem utilizar *Unit of Work*. Além disso, os repositórios foram implementados de forma estritamente síncrona, desprovidos de suporte assíncrono (`Async`).
  - **CQRS (Command Query Responsibility Segregation):**
    - *Avaliação Sênior:* A estrutura de diretórios em `Application/UseCases` organiza as operações em `Commands` e `Queries` ([CreateAnimalCommand.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/CreateAnimal/CreateAnimalCommand.cs), [ListAnimalsCommand.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/ListAnimals/ListAnimalsCommand.cs), [GetAnimalByIdQuery.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/GetAnimalById/GetAnimalByIdQuery.cs)). No entanto, **não se trata de CQRS completo**. Os handlers são injetados diretamente 1-para-1 nos controllers sem uso de um barramento/mediador (padrão *Mediator* / *MediatR* com *Pipeline Behaviors*), e as consultas leem a mesma entidade de escrita (`Animal`), sem projeções otimizadas para leitura.
  - **Configuration Validation & Fail-Fast Pattern:**
    - *Ponto Excelente:* Uso de validações estáticas de configuração na inicialização em [JwtTokenGenerator.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/Security/JwtTokenGenerator.cs), [ClientCredentialsProvider.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/Security/ClientCredentialsProvider.cs) e [AdminSeeder.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/DataBase/AdminSeeder.cs). A aplicação interrompe a subida (*Fail-Fast*) caso faltem segredos ou variáveis críticas de ambiente.

## 2. Princípios de Engenharia de Software
* **SOLID & Clean Code:**
  - **Single Responsibility Principle (SRP):**
    - Os Handlers ([CreateAnimalHandler.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/CreateAnimal/CreateAnimalHandler.cs), [LoginHandler.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Auth/Login/LoginHandler.cs)) possuem responsabilidade única e focada.
    - *Domínio Semi-Anêmico:* A entidade [Animal.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Domain/Entitites/Animal.cs) possui setters privados, mas expõe um construtor de 11 parâmetros e um método `Update` com 11 parâmetros. Trata-se de um mutador genérico ("dumb update") que não expressa comportamentos de negócio com Linguagem Ubíqua (ex: `Adotar()`, `AtualizarStatus()`).
    - *Acoplamento nos Controllers:* O [AnimalController.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Controllers/AnimalController.cs) necessita da injeção explícita de 4 Handlers em seu construtor, aumentando a rigidez da classe.
  - **Dependency Inversion Principle (DIP):**
    - Excelente abstração de serviços de segurança ([ITokenGenerator.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/Security/ITokenGenerator.cs), [IClientCredentialsProvider.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/Security/IClientCredentialsProvider.cs), [IClientTokenValidator.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/Security/IClientTokenValidator.cs)).
  - **Clean Code & Nomenclatura:**
    - O código é limpo, legível e contém excelentes comentários explicando decisões técnicas complexas (ex: a normalização de tempo de hash no [LoginHandler.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Auth/Login/LoginHandler.cs) para prevenir *timing attacks*).
    - *Inconsistências:* A propriedade `approximateAge` em [CreateAnimalCommand.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/CreateAnimal/CreateAnimalCommand.cs) e [UpdateAnimalCommand.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Application/UseCases/Animals/UpdateAnimal/UpdateAnimalCommand.cs) está formatada em **camelCase**, violando a convenção C# PascalCase (`ApproximateAge`). No [AnimalController.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Controllers/AnimalController.cs), há uma instrução `using static Microsoft.EntityFrameworkCore.DbLoggerCategory.Database;` não utilizada.

* **DRY & Reutilização:**
  - **Duplicação de Validação de Enums:** Em `CreateAnimalHandler.cs` e `UpdateAnimalHandler.cs`, as validações de enum (`Species == Species.None`, `Sex == Sex.None`, etc.) foram duplicadas manualmente linha a linha.
  - **Redundância de Conversores JSON:** O candidato escreveu 4 conversores JSON customizados ([StatusJsonConverter.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Serialization/StatusJsonConverter.cs), etc.) com código repetitivo em `ONG.API/Serialization`, ignorando o `JsonStringEnumConverter` nativo do `System.Text.Json` (que inclusive já havia sido registrado globalmente em [Program.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Program.cs)).

* **Guard Clauses:**
  - Aplicação adequada de cláusulas de guarda para retornos antecipados em casos de falha (`if (animal is null) return null;`).
  - *Ponto de Melhoria:* Há duplicidade de responsabilidades de validação (DataAnnotations nos DTOs + `if` manuais nos Handlers lançando `ArgumentException` + captura via Middleware global). Uma arquitetura Sênior centralizaria validações de entrada utilizando bibliotecas como `FluentValidation`.

## 3. Práticas de Mercado e Ecossistema .NET Sênior
* **Performance e Recursos:**
  - **CRÍTICO — Bloqueio Síncrono de I/O (Thread Starvation Risk):** Toda a camada de dados e casos de uso é **100% síncrona**. Operações como `_context.Animals.FirstOrDefault()`, `_context.SaveChanges()` e `query.ToList()` em [AnimalRepository.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/Repositories/AnimalRepository.cs) bloqueiam as threads do servidor HTTP. Em aplicações ASP.NET Core sob carga, o I/O síncrono causa **Thread Starvation**, degrada a escalabilidade e pode travar a aplicação. É indispensável o uso de `async`/`await` e APIs assíncronas do EF Core (`ToListAsync`, `SaveChangesAsync`, `FirstOrDefaultAsync`).
  - **Queries EF Core e Change Tracking:** No método `GetAll` de [AnimalRepository.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.Infrastructure/Repositories/AnimalRepository.cs), as consultas de leitura não utilizam `.AsNoTracking()`. Isso obriga o EF Core a rastrear todas as entidades retornadas na memória, desperdiçando recursos de CPU e RAM.
  - **Filtro Case-Insensitive Ineficiente (`.ToLower()`):** Em `AnimalRepository.GetAll`, a filtragem de `District` e `City` utiliza `a.District.ToLower() == filter.District.ToLower()`. No PostgreSQL, a chamada de `.ToLower()` no LINQ impede o uso de índices de coluna padrão (*non-sargable query*), forçando varreduras completas da tabela (*seq scan*). O padrão recomendado em .NET/Npgsql é utilizar `EF.Functions.ILike(a.District, filter.District)`.

* **Tratamento de Erros e Observabilidade:**
  - **Tratamento Global de Exceções:** Implementação sólida com [ExceptionHandlingMiddleware.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Middleware/ExceptionHandlingMiddleware.cs) integrado a `IProblemDetailsService` e `app.UseStatusCodePages()`, padronizando as respostas de erro conforme a especificação RFC 7807 (ProblemDetails).
  - **CRÍTICO — Ausência de Logging Estruturado e Observabilidade:** O projeto possui **zero chamadas a `ILogger<T>`**. Eventos críticos de segurança (falhas de login, tokens rejeitados em [ClientTokenEnforcementMiddleware.cs](file:///d:/code/Squad%20Academy/Turma%201/animal-adoption-system/back-end/ONG.API/Middleware/ClientTokenEnforcementMiddleware.cs), exceções não tratadas) não geram logs. A aplicação é uma "caixa preta" sem métricas ou rastreabilidade em produção.

* **Testabilidade:**
  - **Qualidade da Suíte de Testes:** A cobertura de testes em `ONG.Tests` é de **excelente qualidade**. Inclui testes de unidade e testes de integração de ponta a ponta com `WebApplicationFactory`, cobrindo fluxos de autenticação, cabeçalhos de segurança (`X-Client-Token`), CORS, serialização de enums e cenários de ataque por tempo (*timing attacks*).
  - **Uso de EF Core InMemory:** Os testes de repositório utilizam `UseInMemoryDatabase`. Em uma avaliação Sênior, destaca-se que o provider In-Memory não simula fielmente o banco relacional (PostgreSQL), pois ignora regras de SQL translation, restrições relacionais e comportamentos de *case sensitivity*. Para testes de infraestrutura confiáveis, deve-se adotar **Testcontainers** com instâncias reais de PostgreSQL em Docker.
